这份笔记只做一件事：用最小的例子，把六个概念一个一个跑起来。

每一章都按同样的顺序写：

  1. 先看一句话原理。
  2. 再写一个很小的界面。
  3. 再写几十行代码。
  4. 运行，看到结果。
  5. 最后才解释关键代码。

正文里的例子都很小，目的是先让你看懂。完整示例项目的代码放在最后附录，用来对照，不要一开始就整包复制。

这份笔记怎么用

  • 按第 1 章到第 6 章的顺序做，不要跳。
  • 每章先照抄“最小界面”和“最小代码”，先让程序跑起来。
  • 跑起来以后，再看“关键代码只看三处”。
  • 报错时先看“常见错误”，大部分问题都在那里。
  • 学完一章，再做一两个小练习，不要一次改太多。

6.1 为什么不是直接 new CounterViewModel()

如果窗口只有一个页面，直接写 DataContext = new CounterViewModel(); 也能用。

但我们的窗口有多个页签，每个页签都有自己的 ViewModel。这时更常见的写法是：先建一个“总”的 MainViewModel，让它把各个页面的 ViewModel 都装起来。

这里用 Command 只是举例，说明一个柜子可以放多个抽屉；CommandViewModel 会在第 3 章创建。现在先理解“总 ViewModel 负责组合页面 ViewModel”就够了。

可以把它想成一个抽屉柜：

  • MainViewModel 是柜子。
  • Counter、Command 是柜子里的两个抽屉。
  • 每个抽屉里放一个页面自己的 ViewModel。

窗口只认柜子，页签再各自去柜子里拿自己的抽屉。

7. 关键代码逐段看

7.1 先拆开 private readonly IMessenger _messenger;

部分 意思
private 私有字段，只有 MessengerPageViewModel 里面的代码能用
readonly 只能在声明时或构造函数里赋值，之后不能再换成另一个 Messenger
IMessenger 字段类型，表示“一个 Messenger 应该能做什么”
_messenger 字段名，下划线是私有字段的常见命名习惯

为什么要在构造函数里写 _messenger = Messenger.Default;？因为后面很多地方都要用 Messenger。每次都写 Messenger.Default.Register(...)、Messenger.Default.Send(...) 会比较长；先把它存到字段里，后面统一写 _messenger，更短，也更容易替换。

readonly 只表示“这个字段不能再指向别的 Messenger”，不表示“不能调用它的方法”。你仍然可以写 _messenger.Send(...) 和 _messenger.Register(...)。

IMessenger 是一个接口。你可以把它理解成“插头标准”：Messenger.Default 是符合这个标准的默认实现。字段写成 IMessenger，以后想换成测试用的 Messenger 也方便。

7.2 Register 这行代码怎么读

部分 意思
_messenger 用哪个 Messenger 来登记
Register<StatusMessage> 登记“StatusMessage 这种消息”
ListenerA 谁要接收，也就是 recipient
ListenerA.Receive 收到消息后调用哪个方法，也就是 action
第三个参数默认 false 不强行把接收者留在内存里

Action<StatusMessage> 可以理解成“一个能接收 StatusMessage 参数、没有返回值的方法”。ListenerA.Receive 正好符合这个形状，所以可以直接传进去。

Visual Studio 提示里的三句话，可以这样翻译：

  1. Registers a recipient for a type of message TMessage.
    意思是：给某一种消息登记一个接收者。
  2. The action parameter will be executed when a corresponding message is sent.
    意思是：有人发送这种消息时，就执行你登记的方法。
  3. Registering a recipient does not create a hard reference to it, so if this recipient is deleted, no memory leak is caused.
    意思是：登记不会强引用接收者；接收者被删除后，Messenger 不会把它一直拽在内存里，所以不会造成内存泄漏。

“强引用”可以理解成：Messenger 手里抓着你的对象，只要它不松手，垃圾回收器就不能回收这个对象。

“弱引用”可以理解成：Messenger 只记了一个联系方式，并不拥有这个对象。对象没有别人使用时，就可以被回收。

keepTargetAlive = false 是默认值，表示使用弱引用。初学阶段保持默认就好。

但要注意：弱引用意味着接收者必须由页面自己保存住。我们的 ListenerA、ListenerB 是 ViewModel 的属性，所以它们一直活着。如果你在方法里临时 new 一个监听器，既不给属性也不保存，它可能被垃圾回收，之后就不再收消息。

如果把 keepTargetAlive 改成 true，Messenger 会强引用接收者，接收者不容易被回收；但如果你忘了 Unregister，反而可能造成内存泄漏。所以初学阶段不要改它，保持默认，并在 Cleanup() 里反注册。

13. 小结与迁移

Messenger 的基本用法就是三步：注册、发送、反注册。以后遇到“一个变化要通知多个对象”，先定义消息类型，再让接收者注册，不要让发送者保存一堆对象。

最小版先不处理窗口关闭；完整项目会在窗口关闭时调用页面 ViewModel 的 Cleanup()。你现在只要知道反注册代码应该放在 Cleanup() 里就够了。

6. DispatcherHelper对象使用

1. 本节目标

后台线程计算进度，界面进度条安全地跟着走。

2. 一句话原理

WPF 控件只能由创建它的 UI 线程修改。后台线程不能直接改控件，要把“更新界面”这个动作交给 UI 线程。

DispatcherHelper.CheckBeginInvokeOnUI(...) 就是用来做这件事的。

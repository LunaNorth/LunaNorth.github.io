前言：EFCore 到底是个啥

先记住一句话：

EFCore 就是一个翻译官，专门帮你把 C# 代码翻译成数据库能听懂的 SQL 语句。

你现在写程序，数据都是存在内存里的，程序一关就没了。做上位机、做数据采集，数据是要长期保存的，比如：

  • 设备台账（每台设备的编号、名称、型号）
  • 采集到的历史数据（温度、压力、产量）
  • 报警记录

这些数据都要存到数据库里。数据库只认一种语言，叫 SQL，长这样：

这行 SQL 的意思是”把价格大于 20 的产品全查出来”。看着还行，但一旦查询变复杂，SQL 就很长、很难写、还容易拼错。

EFCore 干的事，就是让你不用写 SQL，直接用 C# 就能操作数据库。你写 C#，它在背后帮你翻译成 SQL 发给数据库。

打个比方：数据库是一台只会说”数据库黑话”的机器，EFCore 是站在你身边的翻译官。你说普通话（C#），它替你翻译（生成 SQL），再把结果拿回来给你。

用 EFCore 有三大好处：

  1. 不用手写 SQL 语句
  2. 用你熟悉的 C# 就能增删改查，写法跟操作 List 列表差不多
  3. 换数据库方便。你现在用 SQL Server，以后公司若换成 MySQL 或者其他数据库，代码基本不用改，只改一行配置就能切换

所以，学 EFCore 之前，先记住三句话：

  • EFCore 是连接 C# 程序和数据库的一座桥
  • 数据库里的一张表，在程序里对应一个”类”（叫模型类）
  • 操作数据库，就像操作一个 List 列表，记住最后要”保存”

接下来我们一步一步做，每一步你都能亲手跑起来，看到结果。

最后那句 TrustServerCertificate=True 要特别说一下：新版 .NET 默认要求加密连接，而本机 SQL Server 的证书是自己签的，系统不认，就会报错。加上这句，就是告诉程序”本机的证书我信了，别拦我”。

这里有两个地方要重点记住：

第一，15.5m 这个 m 不能省。因为 Price 是 decimal 类型，而 C# 里直接写 15.5 默认是 double 类型，不匹配会报错。在小数后面加个 m，就是告诉 C#：这是 decimal。15.5m 读作”十五块五毛的 decimal”。

第二，SaveChanges() 千万不能忘。db.Products.Add(p1) 只是把 p1 记在”待保存清单”上，还没真正写进数据库。只有调用了 SaveChanges()，数据才真正落盘。忘了这行，程序跑完你会发现数据库里啥都没有。

把这三步连起来记：

Add（加入待保存清单）加 SaveChanges（真正写入）等于数据入库。

第十步：几个容易踩的坑

坑一：忘了 SaveChanges

这是新手最常犯的错。Add 了、改了、删了，结果数据库里没变化，十有八九是忘了 SaveChanges。

记住：Add、改属性、Remove 都只是改动内存里的对象，只有 SaveChanges() 才把改动真正写进数据库。

坑二：小数没加 m

坑三：改了模型类，旧数据库没跟着变

比如你后来给 Product 类加了一个属性，再跑程序会发现报错，说表里没这列。这是因为 SQL Server 里的 MyShop 数据库还是老结构，EnsureCreated 不会去改已经存在的库和表。

坑六：连不上服务器，多半是实例名不对

这是 SQL Server 特有的坑。运行时报错说连不上服务器，最常见的原因有两个：

第一个，实例名不对。如果是 Express 版，实例名通常是 SQLEXPRESS，连接字符串里要写成 Server=localhost\SQLEXPRESS（注意两个反斜杠），而不是 Server=localhost。怎么确认，回第四步的”如果连不上，看这里”。

第二个，忘了写 TrustServerCertificate=True。漏了这句，会报一个和证书有关的错。把它加上就好。

小结

把今天学的东西串起来回顾一遍：

  1. EFCore 是连接 C# 程序和数据库的翻译官
  2. 一个模型类（比如 Product）对应数据库里的一张表
  3. 数据库上下文 AppDbContext 是翻译官，负责建表、操作数据
  4. 连接字符串告诉 EFCore：服务器在哪、进哪个库、用谁登录
  5. EnsureCreated 帮你自动建库建表
  6. 增删改查的套路：查出来、改对象、最后 SaveChanges

用一句话记住整个 EFCore 的入门核心：

把表当成类，把数据当成对象，把操作当成 List，最后记得保存。

下一步可以学什么

入门这一关过了之后，有两条路可以往下走：

第一条路，学”迁移”Migration。正式项目里，数据库结构会不断改，不能每次都删库重建。迁移能帮你安全地升级数据库结构，是实际工作中一定会用到的。

第二条路，学账号密码登录和远程连接。现在你用的是本机的 Windows 身份验证。以后连公司的 SQL Server，往往要改成用账号密码登录，连接字符串里的 Server 也要写成公司服务器的地址。这个等你有具体服务器了再学也不迟。

建议先反复把今天这几步多跑几遍，把增删改查写熟了，再往这两条路走。

2. 数据序列与Y轴

本节目标

完成本章后，你应该能：

  • 在同一个 Plot 中添加多条数据序列。
  • 用图例区分不同业务含义。
  • 固定 Y 轴范围，避免刷新时坐标轴跳动。
  • 判断两条数据是否适合画在同一个 Y 轴上。

一个 Plot 可以有多条序列

Plot 内部维护一个 PlottableList。每调用一次 Add.Scatter，列表中就多一个序列对象：

多条曲线共享同一个坐标系，所以它们的 X、Y 单位必须一致。进口压力和出口压力都可以用 MPa，因此可以共轴；温度与压力如果直接共用一个 Y 轴，即使线画出来了，读数也会误导人。

固定 Y 轴有三个直接好处：

  • 曲线更新时纵轴不跳，眼睛容易比较变化幅度。
  • 同一设备不同批次的截图可以直接并排看。
  • 预警线始终处在固定高度，不会因为自动缩放而看起来“时高时低”。

固定范围不是永远不调整。设备量程、单位或工艺阈值发生变化时，应当由业务规则明确更新范围，而不是让图表悄悄自动缩放。

常见错误

错误 1：第二条线覆盖了第一条

如果两次添加数据时都调用了 plot.Clear()，第一次添加的内容会被清掉。一个页面只应在构建开始时清一次，然后依次添加所有序列。

错误 2：图例中出现两个相同的“压力”

LegendText 是显示名称，不是变量名。给两条线分别写成“进口压力”“出口压力”，而不是都保留默认或同名文字。

错误 3：固定范围后又调用自动缩放

如果后续代码调用 plot.Axes.AutoScale()，它会重新计算范围。固定范围之后，不要在同一刷新流程里又要求自动缩放。

错误 4：不同单位硬塞进一个 Y 轴

温度 ℃ 与压力 MPa 没有可比性。要么统一单位，要么使用额外坐标轴，并在界面中明确说明每条线对应哪一侧的轴。

为什么不能直接把 DateTime 传给 Scatter

ScottPlot 的坐标计算使用 double。DateTime 是结构体，不能直接作为 X 数组元素交给 Add.Scatter。

错误 1：把预警线放进 ys 数组

错误思路：

这会把 80 当成某个时刻的真实采样值，曲线也会被强行拉到一个不存在的数据点。正确做法是使用 HorizontalLine。

错误 2：格式字符串没有生效

先确认刻度生成器确实是 NumericAutomatic。如果之前调用过 DateTimeTicksBottom()，底部轴生成器已经是时间类型，不能再按数值轴强转。

错误 3：轴标题写“压力”，刻度又写“MPa”，但单位不一致

例如轴标题写 kPa，刻度格式化却写 MPa。单位必须在数据、规则、轴标题和刻度之间保持一致。

错误 4：修改后没有刷新

漏掉这一行时，模型已经改了，屏幕却还停留在上一次绘制结果。

小练习

把预警线阈值从 80 改成 75，并同步修改：

  1. 业务判断方法中的阈值。
  2. 预警线的 Y 值。
  3. 图例文字。
  4. 左侧轴刻度的显示格式。

然后增加一条 90 MPa 的红色点划线，观察两条预警线是否能清楚区分。

本章小结

一张可信的工业趋势图，至少要说清四件事：

格式只负责“怎么显示”，数据序列负责“真实值”，预警线负责“业务阈值”。三者分开，图表才容易维护。

写在最后

ScottPlot 的入门门槛不高，但真正写出“可信的图”需要把四层分开：

只要每加一个功能，都能说清它属于哪一层，图表出现空白、标签不对或预警线位置错误时，就不会再靠猜。

下一步可以继续练习：

  1. 把定时采集的数据追加到已有序列，观察实时曲线的滚动效果。
  2. 使用 plot.Axes.Right 增加第二纵轴，比较不同单位的数据。
  3. 用业务规则计算预警状态，并在界面顶部同步显示报警文字。
  4. 把图表封装到用户控件中，让同一套趋势图复用到多个设备页面。

把这篇的四页示例完整跑通，再动手改数据、单位和阈值，你会比只看 API 列表更快建立自己的图表思维。

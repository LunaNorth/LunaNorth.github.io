1.6 TwoWay：双向同步

含义：

编辑类控件经常使用双向绑定，例如：

  • TextBox.Text
  • CheckBox.IsChecked
  • Slider.Value
  • ComboBox.SelectedItem

1.7 OneTime：只读取一次

绑定只在初始化时读取一次来源值。之后来源变化不会继续更新目标。

适合：

  • 启动后不会变化的配置
  • 一次性标题
  • 性能敏感且确定不会变化的静态内容

不要把需要实时更新的内容写成 OneTime，否则很容易出现“值明明变了，界面不动”的问题。

1.8 UpdateSourceTrigger 控制写回时机

对于双向绑定，目标变化后什么时候写回来源，由 UpdateSourceTrigger 控制：

值 含义 适合场景
PropertyChanged 目标属性每次变化就写回 实时搜索、即时预览
LostFocus 目标失去焦点时写回 普通表单
Explicit 调用 UpdateSource() 时写回 需要手动提交
Default 使用目标属性的默认行为 通常不用手动指定

2.1 什么是依赖对象

DependencyObject 是 WPF 属性系统的基础类型。依赖属性必须注册在依赖对象上。

常见依赖对象包括：

  • Window

2.2 依赖属性为什么适合做来源

依赖属性由 WPF 属性系统管理，变化通知是属性系统能力的一部分。绑定读取依赖属性时，可以直接接入这套通知机制。

对比普通属性：

来源属性类型 变化通知
依赖属性 属性系统原生支持
普通属性 通常要实现 INotifyPropertyChanged

这就是为什么控件属性作为绑定来源时通常不需要额外写通知代码。

2.7 依赖对象来源的优点

优点 说明
原生变化通知 依赖属性由 WPF 管理
支持样式和动画 依赖属性可以参与这些机制
支持属性值继承 可以设置 Inherits
与 XAML 配合自然 控件本身就是依赖对象

2.8 依赖对象来源的限制

依赖对象适合界面属性，但不是什么数据都应该做成依赖对象。

限制 说明
必须继承 DependencyObject 普通 POCO 不能直接使用
依赖属性写法较冗长 注册、包装器、元数据
不适合业务实体 业务对象通常使用普通 C# 类和通知接口
需要理解属性系统 调试比普通属性复杂

实际项目中：

  • 控件、视觉属性：依赖对象或依赖属性
  • ViewModel、业务实体：普通类和 INotifyPropertyChanged

2.9 依赖对象和普通对象的对比

对比项 依赖对象 普通对象
基类 DependencyObject 任意类
属性系统 WPF 依赖属性 CLR 属性
变化通知 原生支持 通常实现 INotifyPropertyChanged
样式和动画 原生支持 不直接支持
适合 控件、视觉对象 ViewModel、业务对象

2.10 本节小结

问题 答案
依赖对象可以作为来源吗 可以
依赖属性需要额外通知吗 通常不需要
怎样把依赖对象设为来源 设置目标元素的 DataContext 或使用 Source
适合业务实体吗 通常不适合
适合控件属性吗 非常适合

数据绑定语法速查

写法 含义
{Binding Name} 绑定当前 DataContext 的 Name
{Binding Path=Name} 显式写路径
{Binding ElementName=Other, Path=Text} 绑定另一个元素
{Binding Source={StaticResource Data}, Path=Name} 绑定资源对象
{Binding RelativeSource={RelativeSource Self}, Path=ActualWidth} 绑定目标自身
{Binding RelativeSource={RelativeSource AncestorType=Window}, Path=Title} 绑定祖先窗口
{Binding Employees.Count} 路径访问集合属性
{Binding SelectedEmployee.Name} 路径访问对象属性

绑定模式速查

模式 方向 典型场景
OneWay 来源到目标 只读文本
TwoWay 双向 文本框、复选框
OneTime 只读一次 静态配置
OneWayToSource 目标到来源 特殊场景
Default 目标默认 通常省略

更新时机速查

值 什么时候写回来源 适合
PropertyChanged 目标属性每次变化 实时预览
LostFocus 目标失去焦点 普通表单
Explicit 手动调用 UpdateSource 手动提交
Default 目标属性默认规则 一般不用写

数据来源对照

来源类型 典型对象 通知方式 适合
依赖对象 DependencyObject 依赖属性系统 控件、视觉对象
普通数据 string、int、decimal INotifyPropertyChanged ViewModel 属性
对象 实体类 INotifyPropertyChanged 详情、选中项
集合 ObservableCollection<T> 集合变化通知 动态列表
ADO.NET DataTable、DataView 数据视图通知 表格数据
LINQ List<T>、匿名类型 重新赋值 查询结果

常见错误与排查

现象 常见原因 排查方法
文本为空 路径拼错 查看输出窗口绑定错误
修改来源界面不动 没有通知 实现 INotifyPropertyChanged
修改界面来源不动 没有双向绑定 设置 Mode=TwoWay
输入过程中不更新 写回时机不对 使用 PropertyChanged
列表不刷新 使用普通 List 改用 ObservableCollection
选中项不同步 没有绑定 SelectedItem 设置双向绑定
DataGrid 没有数据 列名与绑定路径不一致 检查列名
LINQ 结果不更新 查询结果已经物化 重新执行查询
绑定没有来源 DataContext 为空 设置 DataContext
转换失败 类型不匹配 使用转换器或格式化

调试绑定的三个步骤

  1. 先看输出窗口有没有 System.Windows.Data Error。
  2. 再确认 DataContext 和 Path 是否指向同一个对象。
  3. 最后检查通知和更新时机。

大多数绑定问题不是 WPF 本身出错，而是来源、路径、通知三者之一没有对上。

最后三个综合练习

练习一：做一个可编辑的员工表单

要求：

  • 使用 Employee 对象作为来源。
  • 姓名、部门、工资都使用双向绑定。
  • 修改表单时，列表中的对应项同步更新。
  • 工资使用 StringFormat 格式化。

这个练习可以检验“对象属性通知 + 双向绑定”。

练习二：给 DataView 增加组合筛选

要求：

  • 增加部门筛选。
  • 增加最低工资筛选。
  • 两个条件可以同时生效。
  • 点击“清除筛选”后恢复全部数据。

提示：RowFilter 可以使用类似 Department = '研发部' AND Salary >= 10000 的表达式。

练习三：做一个实时 LINQ 查询

要求：

  • 文本框中输入关键字。
  • 每次输入后重新执行 LINQ 查询。
  • 查询结果显示在 DataGrid。
  • 输入为空时显示全部员工。

这个练习可以帮助你理解“LINQ 查询结果需要重新赋值”这一行为。

结语

数据绑定看起来有很多写法，但可以先抓住固定关系：

六种来源可以这样记：

来源 核心通知机制
依赖对象 依赖属性系统
普通数据 INotifyPropertyChanged
对象 对象属性通知
集合 ObservableCollection<T>
ADO.NET DataView 的行集视图
LINQ 查询后重新赋值

先把最小的 ElementName 绑定跑通，再依次尝试普通属性、对象、集合、DataView 和 LINQ。每加一种来源，都先观察界面变化，再看通知和路径，理解会比单纯背语法更牢固。

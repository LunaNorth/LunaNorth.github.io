1.9 常见错误

错误一：把按下和自锁写成一个 bool

结果会是”按一下就永久保持”，无法区分短时点动和自锁。

错误二：只处理 Click，不处理 MouseDown / MouseUp

Click 只在一次完整点击结束时触发，不能表示”按住期间一直输出”。

错误三：模板里没有 PART_Button

GetTemplateChild("PART_Button") 会返回 null，鼠标事件不会挂上，控件看起来有外观却没有交互。

错误四：OnApplyTemplate 中只加事件，不减事件

模板重新应用时会重复订阅，一次点击可能触发多次状态切换。

错误五：用颜色表示全部状态

工业界面要考虑色弱、反光和远距离观看，文字、形状、日志同样要表达状态。

1.10 小练习

2.9 常见错误

错误一：把 ​​AffectsRender​​ ** 当成 ​​AffectsMeasure​**

AffectsRender 只请求重绘，不重新测量布局。仪表尺寸通常由 Width、Height 或父容器决定，因此这里使用 AffectsRender 是合适的。

错误二：在 ​​CoerceValue​​ ** 中递归设置自身**

不要在里面再次写 gauge.Value = ...。强制回调返回修正值即可；如果需要更新派生属性，只更新 NeedleAngle 和 IsAlarm。

错误三：修改 ​​Minimum​​ ** 或 ​​Maximum​​ ** 后没有重新强制当前值

量程从 0 - 100 改成 0 - 50 时，原来的 80 已经越界。本例在属性变化时再次调用 CoerceValue(ValueProperty)。

错误四：在 ​​OnRender​​ ** 外直接操作 DrawingVisual**

如果你把 DrawingVisual 塞进 VisualCollection，必须同时正确实现 VisualChildrenCount 和 GetVisualChild，并确保测量逻辑一致。初学者直接用 OnRender 更稳妥。

错误五：角度直接用 0° 到 270°

0° 在右侧、90° 在下方，不符合”左下到右下”的仪表习惯。本例使用 135° 到 405°。

3.5 组件开发顺序

图 10：属性、模板、模板部件、交互和主题五步。

建议按下面顺序做：

  1. 先写状态模型：状态枚举、范围、阈值、单位和格式。
  2. 再做单个控件：不要一开始做十个控件，先做最有代表性的一个。
  3. 然后抽公共规则：把重复的越界修正、报警判断放进规则类。
  4. 最后统一主题：颜色、字号、圆角和间距做成资源或样式。
  5. 每一步都留可运行检查点：值能不能改、异常能不能恢复、换主题会不会坏。

3.6 更多工业组件方向

状态灯

必须同时提供颜色和文字。不要只靠红绿区分，尤其在色弱、强光或远距离环境下。

数值输入

至少要考虑：

上一篇的 NumericBox 已经覆盖了这些基础点，本篇不再重复写完整代码。

报警条

一个报警条至少要有：

如果只显示“压力高报”四个字，操作者无法追溯是哪台设备、什么时候发生、是否已经确认。

设备卡片

设备卡片适合放“名称 + 编号 + 状态 + 两个关键参数 + 操作入口”。不要把整页详细参数塞进卡片，否则总览会失去意义。

工序步骤

工序步骤的核心是“当前步骤、已完成步骤、异常步骤”的区别。颜色只是辅助，序号和文字必须能独立说明状态。

趋势缩略图

缩略图用于总览，不用于精确读数。完整图表可以再点击打开。缩略图可以省略坐标轴标签，但要保留趋势方向和异常点。

3.7 什么时候用 UserControl，什么时候用 CustomControl

简单判断：

例如：

  • StateLamp：组合一个圆点和一个文本块，用 UserControl 很合适。
  • JogSwitch：需要 PART_Button 和默认模板，用 CustomControl。
  • AnalogGauge：绘制逻辑复杂、需要完全自绘，也可以继承 Control 并重写 OnRender。

3.8 运行检查

图 11：六个工业组件方向在页面中的排列。

检查点：

  • 状态灯文字和颜色一致。
  • 数值输入超出范围时能恢复。
  • 报警条有编号、时间、等级等字段。
  • 设备卡片和工序步骤不会挤在同一行互相遮挡。
  • 趋势缩略图只表达趋势，不承担精确读数。

3.9 常见错误

错误一：只做视觉，不做状态

页面看起来像工业界面，但按钮点击后没有任何业务含义。

错误二：把所有组件都做成 CustomControl

组合控件用 UserControl 更快，只有在需要默认模板和换皮肤时才值得做 CustomControl。

错误三：颜色和文字各自维护

状态灯变红，但文字仍写“运行”，操作者会不知道该信哪个。

错误四：组件之间共享可变全局状态

两个设备卡片不应共用一个 IsRunning 字段。每个实例要有自己的数据上下文。

错误五：组件尺寸写死

工业窗口可能运行在 1366×768、1920×1080 或更高分辨率屏幕上。用 MinWidth、MinHeight 和 Grid 的比例布局，比到处写死像素更稳。

4.10 常见错误

错误一：把图表库当 UI 框架

LiveCharts2 不会帮你做导航栏、登录窗口和整套按钮主题。

错误二：为了一个控件引入整套框架

先评估样式冲突、包体积和升级成本。

错误三：只看截图，不看数据量

演示 100 个点很流畅，不代表 100 万个点也流畅。

错误四：不锁定版本

教程代码能跑，不代表未来任意新版本 API 不变。正式项目应在项目文件中固定版本。

错误五：忽略许可证

公司项目、商业项目和个人项目的要求可能不同，必须自行核实。

5.10 常见错误

错误一：只安装 LiveChartsCore

WPF 需要 LiveChartsCore.SkiaSharpView.WPF。只安装核心包时，XAML 中找不到 CartesianChart。

错误二：在饼图上绑定 XAxes 和 YAxes

饼图没有二维坐标轴，Series 和 Legend 才是主要配置。

错误三：X 轴 Labels 数量与 Values 数量不一致

柱子数量和标签数量不对应时，会出现错位或部分标签缺失。

错误四：用 UI 线程之外的代码直接改 ObservableCollection

WPF 集合更新通常需要回到 UI 线程。耗时计算放到后台，结果再通过调度器回到 UI 线程。

错误五：把图表空白都归因于库

多数空白来自数据为空、绑定失败、宽高为 0 或渲染线程问题，不要一开始就更换库。

6.11 常见错误

错误一：每次 Tick 都重建 Series

会导致动画反复启动、图表抖动和性能下降。应该复用集合和 Series。

错误二：集合无限增长

实时运行几小时后，几万个点会让内存和绘制成本越来越高。必须设置滚动窗口。

错误三：在后台线程直接改 ObservableCollection

WPF 控件绑定集合时通常要求 UI 线程更新。需要回到 Dispatcher。

错误四：纵轴范围随数据自动变化

曲线看起来一直在跳，操作者无法比较前后趋势。实时图应优先固定范围。

错误五：用动画掩盖数据问题

动画只影响观感。数据错、坐标错、线程错，都不是动画能解决的。

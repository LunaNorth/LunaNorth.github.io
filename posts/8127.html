拆箱装箱 值类型和引用类型之间的搬运

前面我们认识了各种数据类型。这一篇讲一个让很多新手发懵的词——装箱（Boxing）和 拆箱（Unboxing）。别怕，它俩说白了就是「把值装进盒子、再从盒子取出来」两件事，看完这篇你就能彻底搞懂。

本篇目标：能说出什么是装箱、什么是拆箱，能自己写一段装箱拆箱的代码，并且知道拆箱时最容易踩的坑。

一、先补个前提：值类型 和 引用类型

拆箱装箱是「值类型」和「引用类型」之间的转换，所以得先分清这两类类型。就一句话。

用一个生活比喻分清两类类型

想象你有一笔钱（数据）：

  • 值类型：把现金直接塞进自己的口袋。钱就在口袋里，要用直接掏。比如 int、double、bool、float，它们把「值本身」直接放在变量里。
  • 引用类型：口袋里的不是钱，是一把储物柜的钥匙。真正的钱放在储物柜里，你要用钱，得先拿着钥匙去开柜子。比如 string、object，它们变量里放的是「地址」，真正的数据在别处。

一句话记：值类型装的是值本身，引用类型装的是地址。

分类 常见类型 变量里装的是
值类型 int double bool float long 值本身
引用类型 string object 自定义类 地址（钥匙）

还记得上一篇学的 int、double 吗？它们都是值类型。而 string（字符串）是引用类型，object 是所有类型的「老祖宗」，它俩都是引用类型。记住这两个就够用了。

二、什么是装箱（Boxing）

装箱：把一个值类型（比如 int），装进 object 这个「盒子」里。因为 object 是所有类型的祖先，任何东西都能往里塞。

装箱背后发生了什么？

装箱时，电脑做了两步：

  1. 在「堆」（储物柜区）里开辟一块新空间，专门放这个盒子。
  2. 把 value 的值 100 复制一份，放进盒子里，再把盒子的地址交给 box。

所以装箱不是「把 int 变成 object」，而是「复制一份值，包成一个 object」。原来的 value 还是 int，一点没变。

装箱是隐式的，也就是你什么都不用写，直接赋值 object box = value;，电脑自动帮你装箱。

三、什么是拆箱（Unboxing）

拆箱：把 object 盒子打开，把里面的值取出来，还原成原来的值类型。这次就必须写「强制转换」了。

拆箱背后发生了什么？

拆箱也分两步：

  1. 先检查盒子里装的值，类型是不是 int。
  2. 如果是，就把盒子里的 100 复制出来，交给 value；如果不是，直接报错（这个坑下一节重点讲）。

注意那个 (int) 不能省，它是「拆箱」的标志，告诉电脑我要按 int 来取。

装箱是隐式的（自动），拆箱是显式的（必须写 (类型)）。这是它俩最明显的区别。

四、为什么要拆箱装箱？有什么用？

你可能想问：好端端的 int，干嘛非要装进 object 再取出来？答案是——有些地方只认 object，不认具体类型。

五、拆箱最大的坑：类型必须完全对上

这是新手必踩的坑，务必看仔细。拆箱时，盒子里的类型必须和你拆箱写的类型一模一样，差一点都不行。

为什么 int 不能直接拆成 double？

因为拆箱要求类型完全一致：盒子装的是 int，你就只能用 int 去拆，用 double 去拆会抛 InvalidCastException 异常（程序崩溃）。

六、性能提醒：别没事瞎装箱

装箱要在堆上开新空间、复制数据，是有成本的。如果在一个循环里反复装箱拆箱，程序会变慢。所以结论是——能不用就不用。

什么时候容易不小心装箱？

比如用 + 拼接字符串时，数值会先装箱再拼接。虽然单次看不出差别，但循环几十万次就有感觉了。新手阶段先记住这个意识即可，等学到泛型、集合再回头看会更明白。

七、上位机里的场景

上位机开发里，装箱拆箱常出现在「通用点位」这种需求上：一个变量要能同时存温度、开关、计数等不同类型，就会先用 object 来中转。

八、小结

这一篇我们搞懂了拆箱装箱：

  • 值类型（int double bool）装的是值本身，引用类型（object string）装的是地址。
  • 装箱：值类型塞进 object，隐式自动完成。
  • 拆箱：从 object 取出值，必须写 (类型) 强制转换。
  • 最大的坑：拆箱要同型，盒子里是 int 就只能拆成 int，否则报错。
  • 能不用就不用，装箱拆箱有性能成本。

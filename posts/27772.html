来源写法 来源是什么 适合什么场景

1.8 为什么修改集合后界面不一定刷新

ObjectDataProvider 的方法只执行一次，返回值会成为来源。后续集合内部发生变化时，是否刷新取决于返回值本身是否能通知变化。

对比：

方法返回值 新增一项后是否自动刷新
List<Employee> 不一定，列表本身不提供集合变化通知
ObservableCollection<Employee> 会通知集合变化
每次重新调用方法 需要重新执行提供器

示例中的服务内部保存 ObservableCollection<Employee>，所以集合变化可以被观察到。若方法每次返回新的普通 List<T>，绑定不会凭空知道列表内容已经改变。

2. 基于 XML 数据的数据源使用

本节目标

学完本节，你应该能够：

  • 用 XmlDataProvider 读取内嵌 XML。
  • 用 XPath 选择节点集合。
  • 用 @属性名 读取 XML 属性。
  • 用子元素路径读取 XML 元素文本。
  • 解释 XML 数据源的只读特性和常见限制。

2.1 什么时候使用 XML 数据源

XmlDataProvider 适合：

  • 配置文件、菜单结构、离线数据包。
  • 已经存在 XML 文件，不想先转换成实体类。
  • 需要按 XPath 快速选取节点。
  • 做 XML 结构演示或小型工具。

如果数据来自数据库、Web API 或复杂业务对象，通常优先转换为强类型对象，再绑定到属性。XML 绑定灵活，但字段类型、编辑和验证都不如实体类直观。

2.2 XML 数据源的结构

数据 写法 XPath

2.5 第三步：理解 XPath 绑定

常用 XPath 对照：

写法 含义
Employees/Employee 选择 Employees 下的所有 Employee
@Name 当前节点的 Name 属性
@Department 当前节点的 Department 属性
Name 当前节点的 Name 子元素
Employee[1] 第一个 Employee 元素
Employee[@Department='研发部'] 按属性筛选

示例数据把字段写成属性，因此模板里必须写 @Name。如果写成 XPath=Name，绑定会去找名为 Name 的子元素，而不是属性，结果通常是空白。

2.7 XML 数据源的编辑限制

XmlDataProvider 擅长读取，不等于天然适合编辑表单。

常见情况：

操作 难度

按 XPath 读取字段 简单
直接修改节点并写回文件 需要额外代码
类型转换和业务验证 不如实体类直接

3.6 第五步：区分 DataContext 和 Source

两种写法都能绑定同一个员工，但来源选择方式不同：

写法 来源确定方式 适合
{Binding Name} 当前元素继承的 DataContext 页面和 ViewModel
Source=... 明确写出资源或对象 固定来源、跨层引用
ElementName=... 按元素名找来源 同一界面控件互绑
RelativeSource=... 按元素关系找来源 自己、祖先、模板

不要把所有绑定都写成 Source。页面级数据通常让 DataContext 负责，局部固定来源再用 Source，代码会更容易维护。

如果显式来源是一个已经创建的对象，也可以用 x:Reference 引用命名元素：

x:Reference 和 ElementName 都能按名字找元素。前者常用于资源或模板中的引用，后者在普通页面绑定中更直观。

3.7 第六步：为什么修改 TextBox 后列表也会变

示例的编辑区使用双向绑定：

含义：

设置 作用
Mode=TwoWay 界面和来源双向同步
UpdateSourceTrigger=PropertyChanged 每次输入就写回来源
Employee.Name 的 setter 发出 PropertyChanged

三者缺一不可：

  1. 只写 Mode=TwoWay，默认可能在失焦时才写回。
  2. 没有通知，列表不会知道员工姓名已经变化。
  3. 没有 setter，来源值根本不会被更新。

3.8 DataContext 常见错误

错误 现象 修正
忘记设置 DataContext 绑定没有值 在窗口或父元素设置来源
局部覆盖后仍写外层属性 找不到属性 检查当前元素的最近 DataContext
绑定路径大小写错误 输出窗口提示找不到属性 C# 属性名区分大小写
把普通字段当属性绑定 找不到成员 使用公开属性，不用字段
忘记通知 首次有值，修改后不更新 实现 INotifyPropertyChanged
在错误层级设置 DataContext 一部分绑定正常，一部分空白 从目标元素向上找最近的来源

结语

数据源看起来有五种入口，实际上可以归为三个问题：

对象方法数据源由 ObjectDataProvider 创建和调用；XML 数据源由 XmlDataProvider 和 XPath 读取；DataContext 提供默认来源并沿元素树继承；RelativeSource 按元素关系查找自己、祖先或模板父控件。

初学时不要急着把所有写法都背下来。先让每个页签跑起来，再故意改错路径、类型和层级，观察输出窗口。能把“为什么没有值”查清楚，你对 WPF 数据绑定的理解就已经向前走了一大步。

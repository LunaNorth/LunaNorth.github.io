CSharp常用的基础数值类型

发表于2026-09-02|更新于2026-09-02|CSharp
|字数总计:2k|阅读时长:7分钟|阅读量:
C# 数值类型 装数字的十二只杯子

上一篇我们知道了「数据类型就是装数据的杯子」。这一篇专门讲其中的一大类——数值类型，也就是「能装数字」的类型。把 8 种整数 + 2 种小数吃透，上位机读数据、换算工程量就全通了。

本篇目标：看到 int、double、byte 这些词，能马上说出——是整数还是小数、大概能装多大、上位机里用在哪。

一、先认识两个基础词：位 和 字节

理解数值类型，绕不开两个词。它们不复杂，就是「存储空间」的度量单位。

  • 位（bit）：电脑里最小的单位，只能存 0 或 1，就像一盏只能「开」或「关」的灯。
  • 字节（byte）：把 8 个位打包成一组，就是 1 个字节。
位和字节到底啥关系？

把 8 盏灯排成一排，每盏灯都是 0 或 1，这一整排 8 盏灯就是一个字节。

  • 1 个字节 = 8 个位，能表示 2 的 8 次方 = 256 种组合。
  • 2 个字节 = 16 个位，能表示 2 的 16 次方 = 65536 种组合。
  • 4 个字节 = 32 个位，能表示 2 的 32 次方 = 约 42 亿种组合。

所以字节越多，能装的数越大。下面所有整型的范围，都是这么算出来的。

二、为什么整数要分这么多？（8 种整型）

你可能会问：装个整数而已，怎么搞出 byte / short / int / long 一大堆？答案是两条理由。

理由一：内存大小不同

上位机里有些数据很小（比如阀门开度 0~255），有些很大（比如累计电量、时间戳）。

如果所有整数都用最大的 8 字节来装，就会浪费内存。所以 C# 准备了不同大小的「杯子」，小的用小杯，大的用大杯，内存才不浪费。

理由二：有符号 和 无符号

同样是 1 个字节：

  • 无符号（前面没有 S）：只装正数，比如 byte 是 0 到 255。
  • 有符号（前面带 S）：留一半空间给负数，比如 sbyte 是 -128 到 127。

一句话：有 S 能负数，没 S 全正数。

三、8 种整型逐个看

下面这张表就是整型全家桶，从最小到最大排好。不用背，先混个脸熟，用到时回来翻。

类型 名字 范围 占字节
sbyte 有符号字节 -128 到 127 1
byte 无符号字节 0 到 255 1
short 有符号短整型 -32768 到 32767 2
ushort 无符号短整型 0 到 65535 2
int 有符号整型 约 -21 亿 到 21 亿 4
uint 无符号整型 0 到 约 42 亿 4
long 有符号长整型 约 -9.2 后面 18 个零 8
ulong 无符号长整型 0 到 约 1.8 后面 19 个零 8

最小的一对：sbyte 和 byte

上位机里用在哪
  • byte 最常出现在串口、Modbus 报文里，一个字节一个字节地处理。
  • sbyte 可以装带负号的温度、角度这类小量。

稍大一点：short 和 ushort

上位机里用在哪

老式 PLC（如西门子 S7-200）的单个模拟量通道就是 16 位（2 字节），读上来正好用 short 接。

最常用的主力：int 和 uint

int 是整型里最常用的，绝大多数「普通整数」都用它。没特殊理由，整数就默认写 int。

上位机里用在哪
  • 计件数、扫码枪的物料编号、生产班次号，基本都写 int。
  • 确认不会为负的（数量、用电量），用 uint 表达更清楚。

最大的：long 和 ulong

看数字后面的 L 和 UL 没？没加的话，C# 默认按 int 处理，数字一大就报错。加后缀就是告诉电脑「这是 long / ulong」。

上位机里用在哪
  • 时间戳（从 1970 年 1 月 1 日到现在的毫秒数）必须用 long。
  • 累计流量、开机总时长这类「特别大」的数，也要用 long。

四、带小数的浮点型：float 和 double

整数只能装 1、2、3 这种干干净净的数，要装 3.14、25.6 这种带小数点的，就得用浮点型。浮点型有 2 个常用的，外加 1 个算钱的。

类型 名字 大概范围 精度 后缀
float 单精度浮点 约 ±3.4 后面 38 个零 6~7 位有效数字 必须加 F
double 双精度浮点 约 ±1.79 后面 308 个零 15~16 位有效数字 不用加
decimal 高精度小数 约 ±7.9 后面 28 个零 28~29 位有效数字 必须加 M

float：必须加 F

float 的数字后面必须加 F，比如 36.5F。不加 F，C# 会把它当成 double，塞进 float 里就报错。

double：默认的小数类型

decimal：算钱才用它

decimal 不在这次截图里，但先记个脸熟：金额、计费这种「一分都不能差」的场景，用 decimal 而不是 float / double。它更精确，代价是运算稍慢、占内存稍多。

五、一个必须知道的坑：溢出

「溢出」就是往小杯子里硬倒大桶水，水会漫出来。数据也一样——超过了类型能装的范围，数字会变错。

整数选型时，先想想「这个数最大会到多少」。计件数可能到 21 亿吗？可能就要用 long。这就是选类型的第一原则：宁大勿小，装得下比省内存更重要（尤其新手阶段）。

六、小结

这一篇我们学了数值类型全家桶：

  • 8 种整型：sbyte / byte / short / ushort / int / uint / long / ulong，越往后越大。
  • 2 种浮点：float（加 F）、double（默认）。
  • 1 个算钱的：decimal（加 M）。

记一个口诀：

有 S 能负数，没 S 全正数；小数看后缀（F 是 float，M 是 decimal，double 不用加）。

下一步建议：

  1. 在 Visual Studio 里把每种整型都声明一次、打印一次，看范围和输出。
  2. 故意给 byte 赋一个 300，看编译器报什么错。
  3. 下一篇我们学「变量与赋值」，把这些类型真的装进带名字的盒子里用起来。

04-Modbus RTU通信测试软件开发

发表于2026-08-29|更新于2026-08-29|Modbus
|字数总计:5.7k|阅读时长:20分钟|阅读量:

前一部分我们写好了一个 Modbus RTU 通信库，但那个库是”没有脸”的——你只能在代码里写死参数去调用，看不到也摸不着。这一部分，我们给它配上一张”脸”：做一个图形界面软件，让你在窗口里点按钮、看数据，真正体验”上位机”是什么感觉。

这一部分用的是 WinForm（而不是 WPF）。WinForm 的特点是”拖控件 + 写代码”，不需要写 XAML，非常适合刚入门的你。我们一边拖控件设计界面，一边写事件代码，把这个测试软件一点点做出来。

  1. 先新建一个 WinForm 项目；
  2. 把上一部分的通信库加进来（直接复用，不用重写）；
  3. 拖控件设计界面（4.1）；
  4. 写”参数初始化 + 串口连接”代码（4.2）；
  5. 逐个功能写测试代码（4.3 到 4.9）；
  6. 用 Modbus Slave 模拟从站，跑起来看效果。
  • Visual Studio（推荐 2022）；
  • 已经会一点第 3 部分的内容（知道怎么开串口、怎么调读写方法）；
  • 最好装一个 Modbus Slave 软件，用来模拟从站，方便测试。

准备工作：新建 WinForm 项目

第一步：用 Visual Studio 新建项目

  1. 打开 Visual Studio，点击”创建新项目”；
  2. 搜索”窗体”，选择”Windows 窗体应用“（语言选 C#，框架选 .NET 8 或更高）；
  3. 项目名称填 ModbusRTUTest，位置选你找得到的地方，点”创建”。

创建完成后，你会看到设计器里有一个空白窗体（默认叫 Form1），这就是我们软件的主窗口。

第二步：安装串口依赖包

和第 3 部分一样，需要装 System.IO.Ports：

  1. 右键项目名 ModbusRTUTest；
  2. 选择”管理 NuGet 程序包”；
  3. 浏览搜 System.IO.Ports，安装。

第三步：把通信库加进来

第 3 部分我们已经写好了三个库文件（SerialBase.cs、IModbusRW.cs、ModbusRTU.cs），现在直接复用，不用重写：

  1. 右键项目名 ModbusRTUTest；
  2. 选择”添加”，然后”现有项“；
  3. 找到第 3 部分项目文件夹里的这三个文件，选中加进来。

你的项目里就有了开串口、读线圈、读寄存器等全部能力。接下来我们只需要专心做界面，用这些能力就行。

第四步：认识 WinForm 的三个窗口

左边是”工具箱”，里面装满了各种控件（按钮、文本框、下拉框等），我们要拖的就是它们。

中间是”窗体设计器”，显示窗体的样子，拖进去的控件会实时显示。

右边是”属性”窗口，选中某个控件后，在这里改它的名字、显示文字、大小等。

4.1 Modbus RTU 软件 UI 界面设计

这一节要做什么

设计软件的界面。我们的界面分三块：顶部”串口连接”、中间”功能测试”（7 个标签页）、底部”日志”。

整体布局

区域 控件 作用
顶部 GroupBox（串口连接） 放串口号、波特率等参数，以及打开/关闭按钮
中间 TabControl（7 个标签页） 每个功能一个页，互不干扰
底部 GroupBox（日志） 显示操作记录

认识我们要用的几种控件

Label：标签，就是一行说明文字，比如”串口号”。

ComboBox：下拉框，点一下能选一个选项，比如选波特率。

TextBox：文本框，用来输入内容，比如输入从站地址、寄存器地址。

Button：按钮，点一下触发一个动作，比如”打开串口”、”读取”。

GroupBox：分组框，一个带标题的框，把一组相关控件框起来。

TabControl：标签页容器，顶部有一排标签，点不同标签切换不同页面。

手把手：拖控件、设属性

下面以”串口连接区”为例，演示完整的拖控件流程。其它区域的做法完全一样，照着类推即可。

第一步：拖一个 GroupBox。

在工具箱里找到 GroupBox（在”容器”分类下），按住鼠标左键把它拖到窗体上，松开。它的默认标题是 groupBox1，我们在属性窗口把它的 Text 改成”串口连接”。

第二步：拖 Label 和 ComboBox。

  • 拖一个 Label 到 GroupBox 里，属性 Text 改成”串口号”，Name 改成 lblPort；
  • 拖一个 ComboBox 到它旁边，Name 改成 cboPort。

第三步：照这个套路拖完其它参数。

依次拖出：波特率、校验位、数据位、停止位、从站地址，一共 5 组 Label 加输入控件。它们的 Name 建议按下面的清单来，这样后面写代码时一眼就知道是谁。

第四步：拖两个按钮。

拖两个 Button，Text 分别改成”打开串口”和”关闭串口”，Name 改成 btnOpen 和 btnClose。

  • Name：控件的”内部代号”，代码里用它来操作这个控件，比如 txtSlave.Text。这个必须自己起一个好记的名字。
  • Text：控件”显示出来的文字”，是给用户看的，比如”打开串口”。

新手最容易混淆这两个。记住：Name 是给代码用的，Text 是给人看的。

读线圈、读寄存器的结果框，以及日志框，都要设成”多行只读”：选中控件，在属性窗口里把 Multiline 设为 True、ReadOnly 设为 True、ScrollBars 设为 Vertical。这样它们只显示内容，不能被用户乱改，内容多了还能滚动。

TabControl 默认没有标签页，需要点它右上角的小三角，选”添加选项卡”来添加 TabPage，并把每个 TabPage 的 Text 改成”读线圈””读寄存器”等。标签页里的控件要拖到对应的页里，而不是拖到窗体空白处。

运行测试：用 Modbus Slave 模拟从站

软件写好了，但”读”需要有设备回应才有数据。手头没有真实 PLC 也没关系，用 Modbus Slave 软件模拟一个从站即可。

测试步骤

  1. 打开 Modbus Slave 软件，建立一个从站（比如站号 1，功能码 03 读保持寄存器）；
  2. 在 Modbus Slave 里设置几个寄存器，填上一些值（比如地址 0 填 100，地址 1 填 200）；
  3. 如果用串口，先用 VSPD 虚拟一对串口（比如 COM3 和 COM4），Modbus Slave 连 COM4，我们的软件连 COM3；
  4. 回到我们自己的软件，选好串口和参数，点”打开串口”；
  5. 切到”读寄存器”页，从站地址填 1，起始地址 0，数量 2，点”读取”，结果框里应该出现 100 和 200；
  6. 再切到”写单寄存器”页，把地址 0 的值改成 300，点”写入”，然后回到 Modbus Slave 看，那个值已经变成 300 了。

当你在自己写的软件里点一下”读取”，结果框里蹦出真实的寄存器数值时，你就完整走通了”上位机软件”的全过程：界面、串口、协议、数据，全都打通了。

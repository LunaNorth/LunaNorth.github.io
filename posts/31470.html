WPF MVVM 与 ScottPlot 实时数据学习笔记：巡检数据监控台

这份笔记根据本次目录编写，主题是把 MVVM 的分层、集合、命令，与 ScottPlot 的图表数据源和实时刷新连成一条完整链路。

配套案例是一个“巡检数据监控台”。它不追求堆叠控件，而是用五个页签分别观察：

  1. 项目如何分层。
  2. 集合数据怎样接到列表。
  3. 列表中的每一行怎样发出命令。
  4. 数组数据怎样变成 ScottPlot 曲线。
  5. 定时采样怎样持续更新图表。

适合谁

本笔记面向刚接触 WPF 和 MVVM 的初学者。开始前最好已经能创建 WPF 项目，认识 XAML、控件、事件和简单的 C# 类。

不要求你事先会写 ScottPlot 图表，也不要求使用某个 MVVM 框架。示例只使用 .NET 自带接口和手写的两个基础类，便于看清每一步发生了什么。

这份笔记解决什么问题

很多初学者学完 MVVM 后仍会遇到这些具体问题：

  • 文件分了文件夹，但不知道谁应该调用谁。
  • List<T> 能显示，运行时新增一行却不出现。
  • 选中项绑定了，但命令拿不到当前行。
  • 图表能画一次，换数据后不知道何时重画。
  • 定时器能跑，但曲线不跟随新数据移动。
  • 代码“看起来能跑”，却没有可重复的自测和截图验证。

本笔记通过一个共享巡检数据源，把这些问题放进同一条可观察链路：

推荐学习顺序

严格按目录顺序学习：

  1. 先看清项目结构与依赖方向。
  2. 再把服务数据接成可观察集合。
  3. 再给集合增加命令，尤其是行级删除命令。
  4. 再把同一份数据投影成数组，创建 ScottPlot 系列。

1、MVVM项目结构

本节目标

理解 MVVM 项目结构不是“多建几个文件夹”，而是让不同对象承担不同职责，并固定依赖方向。

学完后，你应该能够回答：

  • 为什么 View 不直接操作数据集合。
  • 为什么 ViewModel 不应该创建 WpfPlot。
  • 为什么 Service 不应该引用 WPF 控件。
  • 为什么 Model 只描述一条巡检采样。

通俗原理说明

可以把程序想成一家巡检站：

角色 项目中的对象 负责什么 不负责什么
前台 View 展示界面、接收输入 不保存业务历史
调度员 ViewModel 保存页面状态、命令、图表刷新状态 不创建窗口控件
业务员 Service 查询、追加、删除采样 不知道按钮叫什么
档案 Model 记录时间、站点、温度、振动 不负责显示

“不用分层会怎样？”

如果把按钮点击、校验、数据修改和界面刷新全部写在窗口后台代码中，刚开始确实很快，但后面会出现：

  • 业务逻辑无法单独测试。
  • 同一份数据在多个窗口重复维护。
  • 控件改名或界面重排会破坏业务代码。
  • 图表刷新和数据处理纠缠在一起。

MVVM 的价值不是让文件看起来整齐，而是让数据流和操作路径可追踪。

2、分层架构下的集合数据对接

本节目标

掌握 ObservableCollection<T> 与 ListBox 的对接方式，理解集合变化通知、选中项绑定和筛选属性通知。

通俗原理说明

普通 List<T> 只保存数据，不负责通知界面。

可以把它想成一摞纸质名单：你往里面加一张纸，名单本身不会主动按铃告诉前台。ObservableCollection<T> 则会在增加、删除、清空时发出通知，WPF 的列表控件听到通知后刷新显示。

集合绑定有两个不同问题：

问题 绑定入口 典型属性
有哪些行 ItemsSource Points 或 VisiblePoints
用户选中哪一行 SelectedItem SelectedPoint

如果这两个问题混在一起，就容易出现“列表变了但选中项没变”或“选中项变了但详情没刷新”的问题。

3、集合绑定中的命令处理

本节目标

掌握集合页面中的两类命令：

  1. 页面级命令：新增整张表单。
  2. 行级命令：删除用户点击的那一行。

学完后，你应该能解释为什么删除按钮必须传 CommandParameter，以及为什么命令的 CanExecute 不能只依赖“当前选中项”。

通俗原理说明

命令可以理解为“界面上的动作按钮”和“ViewModel 中的业务动作”之间的合同。

一个命令包含两件事：

成员 作用 示例
Execute(parameter) 真正执行动作 新增采样、删除指定行
CanExecute(parameter) 判断当前能否执行 输入有效、参数是行对象

在 ListBox 的 DataTemplate 中，按钮的 DataContext 是当前行对象，而命令通常属于整个页面 ViewModel。因此需要：

  • 用 RelativeSource 找到外层 UserControl。
  • 用 DataContext.DeleteSelectedCommand 找到页面命令。
  • 用 CommandParameter="{Binding}" 把当前行对象传给命令。

“不用参数会怎样？”

命令只能读取 SelectedPoint。如果用户直接点击某一行右侧的“删除此行”，但这一行没有被选中，删除目标就可能不是用户以为的那一行。

跟做检查点

  • 能解释 CommandParameter="{Binding}" 传的是当前行对象。
  • 能解释 RelativeSource 为什么能找到页面命令。
  • 删除逻辑使用的是参数对象，而不是隐式选中项。
  • 删除后集合与 Service 数据保持同步。
  • 输入无效时新增命令不可执行。

常见错误与解决方法

错误一：在行模板里写 Command="{Binding DeleteSelectedCommand}"，命令始终找不到。

解决方法：行模板的 DataContext 是 InspectionPoint，不是页面 ViewModel。使用 RelativeSource 找到外层控件，再访问它的 DataContext。

错误二：删除命令忽略参数，只删除 SelectedPoint。

解决方法：在 Execute 和 CanExecute 中都接收参数，并根据参数对象处理。

错误三：删除集合后没有删除服务数据。

解决方法：先调用 Service 的业务删除方法，成功后再更新集合；或者反过来后确保失败时回滚。本示例采用前者。

错误四：命令状态变化后按钮仍不亮。

解决方法：在属性 setter 中调用 RaiseCanExecuteChanged()。

4、ScottPlot的基本绑定逻辑

本节目标

理解 WpfPlot、Plot、Scatter 三者的分工，掌握把 X、Y 数组绑定到图表的最短流程，并知道什么时候需要重新创建系列和刷新。

通俗原理说明

ScottPlot 5 的 WPF 控件叫 WpfPlot，但真正保存标题、坐标轴和系列的是它的 Plot 属性。

可以把它们想成：

对象 角色 负责什么
WpfPlot 画框 在 WPF 界面中占位、显示和请求刷新
Plot 画布模型 保存坐标轴、字体、图例和系列
Scatter 一条曲线 保存 X、Y 数据并负责绘制点线

“不用数组绑定会怎样？”

如果每次刷新都直接操作界面元素，或者把绘图逻辑散落在按钮事件中，就会出现：

  • 数据源和图形对象混在一起。
  • 切换指标时不知道旧系列是否要清除。
  • 新增数据后曲线没有变化。
  • 图表无法脱离窗口进行数据层测试。

  • 怎样避免图表越画越慢。

通俗原理说明

实时图表的“实时”来自数据不断追加，不来自控件不断重建。

常见错误与解决方法

错误一：定时器每次 new WpfPlot()，旧控件越堆越多。

解决方法：控件只创建一次，持续更新的是集合、数组和 Plot 系列。

错误二：集合有新数据，但曲线不动。

解决方法：检查是否订阅了 CollectionChanged，以及 RenderPlot() 是否执行到 Refresh()。

错误三：运行时抛出跨线程访问异常。

解决方法：使用 DispatcherTimer，或者把后台线程的数据通过 Dispatcher.Invoke 切回 UI 线程。

错误四：运行几分钟后越来越卡。

解决方法：限制集合长度，并让 X 轴只显示最近一段数据。

错误五：图表在窗口加载前就尝试渲染，出现空引用或布局异常。

解决方法：在 Loaded 事件后再首次渲染，或者在渲染入口检查 IsLoaded。
